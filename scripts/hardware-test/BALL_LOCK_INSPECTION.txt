Ball-lock inspection (explicit CLI or touchscreen opt-in)

The tester_sync_session.py --inspect-ball-lock selection is an explicit stopped
inspection. It never prepares camera/OPS, arms a trigger, or requests a swing.
Normal capture and native fusion retain their existing shot path. Do not swing
during an inspection.

Touchscreen: configure --internal-sync-diagnostic-package PATH on the tester,
then explicitly select Start ball-lock inspection on /internal-sync.html.
The normal Start capture session button never selects diagnostics. The package
must be the separately matched diagnostic package; normal packages do not
enable this control. Mode is immutable for the session, including refresh and
retained status. New starts after terminal sessions require released resources
and completed normal-boot restoration. Evidence from earlier sessions remains.

For the first empty/still control, leave the lane empty throughout and stay
still. Do not add a ball merely because background learning has finished.
A later deliberate placement check may add a ball after learning finishes;
the software does not verify the physical condition of either check. The first
reported lock stops the radar before any OPS/camera preparation. Timeout and
Stop retain available evidence. A saved trace is not verified ball presence or
a correction to false locks. No RESET is needed between inspections while the
same loaded session stays open. Explicit Next/Retry requires the existing
stopped-runtime checks and creates a new attempt; no shot plan advances.
End closes the owner; inspection Resume after closure is unsupported.

The page labels failed/partial exports honestly and offers only files observed
on disk from the allowlisted set below. Stop/End acknowledgement alone is not
a verified stopped runtime. Keep power and USB connected until cleanup and
restoration guidance finish; do not press RESET while stopping or saving.

Read-only preflight (no devices opened):
  uv run --no-sync scripts/hardware-test/tester_sync_session.py \
    --clock-package PATH_TO_MATCHED_DIAGNOSTIC_PACKAGE --inspect-ball-lock

The diagnostic manifest/image/source identity is pinned separately in
run_joint_clock.DIAGNOSTIC_PACKAGES. The normal package and shot-dump allowlists
are unchanged. Old normal packages cannot issue this binary command. The
experimental package is refused by the normal session selection. Source-only
research descriptors cannot qualify. --resume-zero-attempt is refused here.

When an independently authorized execution adds --execute --output NEW_FOLDER,
the existing SessionFiles switch/reset/Next controls and open_runtime UART owner
are used. Each finite RF attempt learns background and stops immediately when
the existing wait_ball callback first observes state=locked (including reason=gone),
before further status commands or companion preparation. This is a host
observation, not proof that the detector's first acquisition was retained.
Faulty/inactive stats rejected before that callback remain in the journal and
cannot produce a first-observed-lock claim. Timeout or operator Stop also
exports when framing is known. Stop acknowledgment and verification precede
export; firmware independently gates full quiescence. Unknown framing forbids
recovery writes. Retry uses the existing explicit stopped-runtime safety proof;
incompatible state refuses instead of inventing a resume path.

Every attempt has a new attempt_id and a directory containing RESULT.json and
iwr-exchanges.json. The ball-evidence subdirectory holds reply.bin (exact bytes,
including partial replies on errors), exchange.json (write count/read times,
owner/package identity/errors), decoded.json (strict raw float32 words) and
coverage.json. Result status is diagnostic_saved_unqualified, never a captured
shot; planned shot activity does not advance. Host receipt times are not sample
or contact times. A failed stop or ambiguous exchange ends the session.

Only source-derived canonical OFBLTR01 header/body + Done\nDone\nl3dump:/>
framing is accepted. The 20-byte header is bounded before payload allocation;
maximum complete reply is 15,739 bytes. No binary prompt search, CRLF
normalization, flush, serial reconfiguration or retry occurs. Hardware console
framing remains unvalidated; failure preserves evidence and poisons the owner.

Coverage is initially structural/session-bound only. It reports current-context
prefix, overwritten/discarded calls and starting locked state. It does not claim
an independently verified transition. Run the separately pinned offline C
analyzer against ball-evidence/reply.bin on a development host to establish
checkpoint closure/retained transitions. No C/WSL compilation runs on the Pi.
Physical ball identity, timing, target arithmetic parity and false-lock correction
remain unqualified.
