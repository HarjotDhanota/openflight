**Note a trap:** `openflight-battery` was created with
`git worktree add -b feat/battery-status upstream/main`, so it **tracks `upstream/main`**.
`git pull` there merges upstream's main rather than fetching your own branch. Repoint it:

```bash
git -C openflight-battery branch --set-upstream-to=origin/feat/battery-status
```

## 3. The active work: battery/power subsystem

**Status: code complete, never run on hardware.**

Battery percentage and 5V-rail health in the app header, with opt-in automatic shutdown.
30 commits, 32 files, ~7,000 lines. Full test suite passes (120 feature tests).

- Design: `docs/superpowers/specs/2026-08-07-battery-status-design.md`
- Plan: `docs/superpowers/plans/2026-08-07-battery-status.md`

### The immediate next action

Run it on the Pi. The plan's "Verification on the Pi" section has seven checks; **steps 5
and 6 are the ones that matter**, because they cover behaviour with *no automated test at
all*:

- **Step 5 — the heartbeat.** Leave it running at a steady level and confirm the
  percentage keeps updating. Without the heartbeat the number freezes until a level
  changes, and only a real session shows that.
- **Step 6 — the shutdown path.** With `--power-shutdown` and `shutdown_volts` temporarily
  raised above the current pack voltage: confirm the countdown ticks once per second,
  that **"Keep running"** cancels it, and that it does not re-arm afterwards.

`renderToString` cannot run effects or dispatch clicks, so the countdown tick, its
re-sync on reconnect, and the cancel button have never been exercised by anything.
`systemctl poweroff` is stubbed in every test and has never executed.

Also re-run `uv run pytest tests/` on the Pi. Four failures on Windows are environmental
(POSIX 0600 mode, udev alias, TrackMan BOM, a flaky simulator-backoff timing test) and
three should pass on Linux.

### Hardware facts already verified — do not re-derive

| Fact | Value |
|---|---|
| Fuel gauge | MAX1704x, I²C `0x36`; reg `0x02` volts, `0x04` ModelGauge SOC |
| Byte order | SMBus little-endian, gauge big-endian — swap every word |
| Worked example | `0x60cc` → `0xcc60` = 52320 → **4.088 V** |
| Power-loss line | GPIO 6, active low. `hi` = wall, `lo` = battery. Confirmed both ways |
| Pin setup | Needs `pinctrl set 6 ip pu` first; reads `no ... --` until configured |
| Rail | `EXT5V_V` is `volt(24)` in `vcgencmd pmic_read_adc` |
| Idle baseline | rail 5.211 V min, pack 3.850 V, `throttled=0x0` |
| Charging | Pack 3.850 → 4.088 V on wall power. Charge current inflates voltage |

## 5. Two upstream defects to report to jewbetcha

Both pre-existing, both found by hitting them. Neither is caused by this work.

**The eslint pre-commit hook is broken.** `.pre-commit-config.yaml` ran `npm run lint`
from the repo root, which has no `package.json` — the UI package is in `ui/`. This blocks
*any* commit touching `ui/src`. It stayed hidden because `files: ^ui/src/.*\.(ts|tsx)$`
means the hook only fires when UI sources are staged, and nothing had staged any since it
was written. Fixed on this branch in an isolated commit, `36e5347`, using
`npm --prefix ui run lint`. **Cherry-pick or drop it independently** — it is unrelated to
the feature and is deliberately its own commit.

**Ruff version skew.** The hook pins **v0.9.10**; the venv has **0.16.2**, which changed
formatting rules. `uv run ruff format --check src/openflight/` — a documented gate in
`CLAUDE.md` — fails on 9 files on a clean checkout, 148 repo-wide. Not fixed here:
reformatting the repository is a maintainer decision, not something to bury in a feature
PR. Either the pin moves to 0.16.x and the repo is reformatted once, or ruff is pinned in
`pyproject.toml` to match the hook.
